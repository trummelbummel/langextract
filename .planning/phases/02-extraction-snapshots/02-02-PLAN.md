## Phase Goal

**As a** developer reading the trace, **I want to** see empty parses, unaligned extractions, and duplicates stated explicitly in the parse → align pair, **so that** an empty list or a failed grounding is never mistaken for missing output or for a parse-stage result.

## Acceptance Criteria

- [ ] Real `Resolver.resolve` returning `[]` prints `0 extractions`, `parse: []`, `align: []` (STG-05 empty)
- [ ] Unaligned extraction: parse line `None`, align line `ungrounded` from config (STG-05 / ROADMAP criterion 2)
- [ ] Duplicates paired by position in stable order; count/identity mismatch and non-snapshot input raise (STG-08)
- [ ] Catalog stdout unchanged

| `config.yaml` (extended) | `ungrounded_label: ungrounded` display constant (D-10) |

## Planner assumptions (specless edges)

- **Empty / single / null:** empty → explicit `[]` lines; single → one pair; `None` is not a valid resolve result (no special case; `snapshot_extractions(None)` may raise TypeError naturally).
- **Adjacency / equality:** equal class+text at two positions are two pairs; touching spans `[0, 5)` and `[5, 9)` print as two separate pairs.
- **Ordering:** position order from resolve, stable; no sorting by span or index.
- **STG-08 "same extractions":** same count and same (class, text) per position; otherwise ValueError — a mismatch is a probe bug the developer must see, not something to paper over.
- **Unaligned rendering:** applies to the align side only; parse side always shows raw `None` because "not yet grounded" is the parse contract.
