## Phase Goal

**As a** developer reading the trace, **I want to** print ungrounded (parse) and grounded (align) field copies of the same extractions, **so that** parse and align stay a before/after pair even though `Resolver.align` mutates the objects `Resolver.resolve` returned.

## Acceptance Criteria

- [ ] Parse snapshot of real `Resolver.resolve` output shows `char_interval=None` / `alignment_status=None` and keeps showing it after `Resolver.align` ran (STG-05)
- [ ] Align snapshot of the same extractions shows `[18, 26)` / `match_exact` for the grounded one; printed block pairs parse line then align line per extraction (STG-08)
- [ ] `python scripts/trace_extract.py` catalog output unchanged; only `scripts/trace_extract.py` + test file touched

## Artifacts this phase produces

| Artifact | Role |
|----------|------|
| `scripts/trace_extract.py` (extended) | `ExtractionSnapshot` frozen dataclass, `snapshot_extractions()`, `print_grounding_pair()` — not called from `main()` yet (Phase 4 wires them into resolve/align wrappers) |
| `tests/trace_extract_test.py` (new) | absltest loading the script via `importlib.util`, exercising real `Resolver.resolve` → `Resolver.align` offline |

## Planner assumptions (specless edges, lifted from coverage probe)

- **Ordering (STG-05):** Pairing is by position. `Resolver.align` yields the same objects in resolve order (verified locally: `out[0] is ex[0]`). Equal class+text extractions stay separate positions; output order is resolve order, stable.
- **Adjacency (STG-05):** Touching spans (`[a, b)` then `[b, c)`) or duplicate texts are never merged — one snapshot per extraction.
- **Empty (STG-05):** Empty input yields an empty tuple; explicit empty-list rendering and the `ungrounded` label land in 02-02. `None` input is not a resolve result and is not accepted.
- **Same extractions (STG-08):** "Same logical extractions" = same position with equal `extraction_class` + `extraction_text`; the mismatch guard lands in 02-02.
- **main() unchanged:** Phase 1 D-01 locks catalog-only stdout; snapshot printing is exposed as functions and proven by the test. Live wiring is Phase 4.

| Snapshot → stdout | Extraction text/attributes from the (local) sample are printed |

| T-02-02 | Repudiation (misleading record) | parse record printed after align | medium | mitigate | Parse record is a frozen copy taken at resolve return; test proves it stays ungrounded after align |
| T-02-03 | Information Disclosure | `print_grounding_pair` stdout | low | accept | Local sample text only (Pitfalls security table); attributes are extraction fields, not kwargs — `redact()` applies to kwargs printing in Phase 4 |
